# Kịch bản Thuyết minh — Phần 3: Automation & CI/CD

## Slide 19 — Chuyển phần 3: Automation & CI/CD (Section Divider)
- **Mục tiêu**: Báo hiệu bước vào phần tự động hóa và tích hợp liên tục.
- **Lời thoại gợi ý**: "Sau khi xây dựng bộ test suite, câu hỏi tiếp theo là: Làm sao để kiểm thử chạy tự động trong quy trình phát triển? Chúng ta sang Phần 3: Automation & CI/CD."

## Slide 20 — Newman — CLI Runner
- **Mục tiêu**: Giới thiệu công cụ CLI Newman để thực thi Postman Collection không cần GUI.
- **Lời thoại gợi ý**: "Newman là công cụ dòng lệnh cho phép chạy Postman Collection trực tiếp trên terminal hoặc server CI, tự động xuất báo cáo HTML và JUnit XML."

## Slide 21 — GitHub Actions — Newman Pipeline
- **Mục tiêu**: Phân tích pipeline tự động chạy kiểm thử API khi có Pull Request.
- **Lời thoại gợi ý**: "Pipeline GitHub Actions tự động kích hoạt service, đợi healthcheck, thực thi Newman runner và tải báo cáo kiểm thử lên làm Artifact."

## Slide 22 — GitHub Actions — Pact Pipeline (Part 1 - Architecture & Jobs)
- **Mục tiêu**: Giải thích quy trình 3 job của Pact Verification Pipeline.
- **Lời thoại gợi ý**: "Pipeline Pact gồm 3 bước rõ ràng: Job Consumer sinh file Pact, Job Provider thực hiện verification thực tế, và lệnh `can-i-deploy` đóng vai trò cổng kiểm soát chất lượng."

## Slide 23 — Pact Verification: local artifact vs Broker (Part 2 - Execution Modes)
- **Mục tiêu**: Phân biệt giữa xác minh qua file artifact cục bộ và qua Pact Broker.
- **Lời thoại gợi ý**: "Hệ thống hỗ trợ cả 2 chế độ: xác minh nhanh bằng local artifact trong môi trường lab, và kết nối Pact Broker/PactFlow khi triển khai quy mô lớn."

## Slide 24 — Giá trị của Automation
- **Mục tiêu**: Tổng kết lợi ích của việc kết hợp Newman và Pact trong CI/CD.
- **Lời thoại gợi ý**: "Sự kết hợp giữa Newman (bắt lỗi chức năng) và Pact (bắt lỗi tương thích) tạo nên lá chắn tự động hóa vững chắc trước khi code được merge."
