## Slide 45 — API Testing vs Contract Testing
- **Mục tiêu**: Đặt hai lớp kiểm thử cạnh nhau để làm nổi bật sự bổ trợ lẫn nhau.
- **Lời thoại gợi ý**: "Tóm lại, API Testing tập trung kiểm tra chức năng nội bộ từng endpoint, còn Contract Testing tập trung bảo vệ tính tương thích giao tiếp giữa các service độc lập."

## Slide 46 — Khi nào dùng gì?
- **Mục tiêu**: Hướng dẫn khung quyết định chọn loại test dựa trên quy mô và kiến trúc hệ thống.
- **Lời thoại gợi ý**: "Dùng API testing khi cần validate logic chi tiết hoặc hệ thống Monolith; dùng Contract testing khi hệ thống chuyển sang Microservices có nhiều nhóm phát triển song song."

## Slide 47 — Adoption Path — Bắt đầu thế nào?
- **Mục tiêu**: Đề xuất lộ trình 4 bước để áp dụng Contract Testing vào dự án thực tế.
- **Lời thoại gợi ý**: "Đừng cố làm tất cả cùng lúc. Lộ trình gợi ý: Bắt đầu từ 1 API rủi ro cao -> Tạo contract tiêu chuẩn -> Đưa vào CI pipeline -> Tích hợp Pact Broker và Quality Gate."

## Slide 48 — 3 từ khóa
- **Mục tiêu**: Chốt lại thông điệp cốt lõi của bài thuyết trình với 3 từ khóa: Fast, Focused, Safe.
- **Lời thoại gợi ý**: "Ba từ khóa đọng lại hôm nay: Nhanh chóng (Fast) trong phản hồi, Tập trung (Focused) đúng phạm vi rủi ro, và An toàn (Safe) trước mọi quyết định deploy."
